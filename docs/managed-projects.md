# Managed projects and Windows credentials

Tracking: [issue 52](https://github.com/ValenFelizia/instagram-to-opendesign/issues/52), [source PR 61](https://github.com/ValenFelizia/instagram-to-opendesign/pull/61), VAL-100. Source and prerequisite [PR 60](https://github.com/ValenFelizia/instagram-to-opendesign/pull/60) are operator-merged into main through `dd4a1db`, verified 2026-10-04. Native manual gates remain open. This increment persists local projects and provider configuration; it does not run the pipeline or grant paid authorization. Issue 53 adds a separate [transactional job kernel](transactional-jobs.md) and writer interlock: backup/trash/restore block an active writer, exclude control markers from backups and revoke job approval on moves.

## Operations

- **New project:** enter a name and optional Instagram profile URL. The default is `<LocalAppData>/Instagram to OpenDesign/workspace/projects/<uuid>`. An advanced native folder selection creates a new UUID child, never adopts or overwrites the selected parent. Pick an ordinary local disk without synchronization; UNC paths and linked/aliased ancestors are refused. Mapped network drives and third-party synchronization cannot be reliably identified by this broker; they are outside supported active storage.
- **Import folder:** select one legacy CLI profile folder, not an entire checkout. Review file count and total bytes, then explicitly copy. The selection is an opaque, single-use ten-minute capability. Inventories and SHA-256 checks detect source changes before/during/after copying. Original bytes are never rewritten. A recognized normalized source retains its username as the copied data folder; a conflicting entered profile fails. Unrecognized legacy bytes remain an opaque `data/imported` snapshot, not a schema-validated analysis. No migration or provider call occurs.
- **Open:** select a registered project. Registry identity, UUID directory and on-disk metadata must agree. Imported HTML/SVG are inert stored bytes; this increment never opens them as privileged previews. Report/artifact preview integration remains later work.
- **Copy backup:** explicitly select one project's complete backup scope, confirm that it includes private evidence/photos/results, then choose a destination. A fresh folder receives the inventoried project bytes. Credentials, settings, registry and diagnostics are outside that tree. This is a directory backup, not an agent handoff or a ZIP restore feature. A user-selected synchronized destination may upload data through that user's software; the app itself never uploads it.
- **Trash / Restore:** confirm the selected project; move only its owned UUID folder to the adjacent app-owned `trash` folder. Restore reverses this operation. Imported originals and independent backups are untouched. No permanent deletion, automatic purge or secure-erasure claim.

The project picker and confirmations are native Windows dialogs. Cancellation has no effect. Closing/crashing the view revokes any pending native operation's authority; reopening does not authorize a new copy or deletion. IPC carries fixed actions, bounded fields, project IDs and import capabilities, never renderer-chosen filesystem paths. The main process serializes operations.

## Files and containment

Every existing ancestor is checked with `lstat` and native `realpath`. Refuse symbolic links, Windows junctions, hardlinked files, short-name aliases, UNC paths, path traversal, alternate streams, reserved Windows filenames, trailing spaces/dots, hidden files, secret/configuration-like filenames and case-folded duplicate paths. Import allows JSON/HTML/CSS/Markdown/text, selected image/video/font formats and PDF; no executable/script/archive extraction. ZIP files are refused entirely, so archive traversal is not an extraction path. Limit imports/backups to 2000 files, 4000 entries, depth 40, 32 MiB per file and 256 MiB total. Unsupported trees fail visibly instead of silently omitting files.

Cleanup checks its resolved absolute target under the newly created parent, removes inventoried files individually, then empty directories. It never recursively deletes a user-selected parent, workspace, source or credential store. Registry parse/version/duplicate failures fail closed without resetting the registry. Normal import/write failures remove only this attempt's fresh copy. Normal trash/restore registry-write failures roll the move back. Errors are fixed allowlisted codes/action names; raw exceptions, paths, captions, provider payloads and keys are not returned or logged.

Containment checks protect the broker from untrusted input; they do not create an OS boundary against malicious concurrent filesystem replacement by another program running as the same Windows user. Use app-owned storage without external concurrent writers. Hash equality verifies copied file bytes and relative inventories, not timestamps, ACLs, filesystem metadata or arbitrary secrets embedded by the operator in otherwise allowed evidence. Do not place keys in evidence files; the app's own keys are always separate.

## Credentials

Apify and OpenAI keys are operator-wide and write-only through Settings. New password input is transiently submitted to main, immediately cleared, and cleared again on provider change/dialog close. JavaScript cannot guarantee erasure from process memory; “no renderer state” here means no retained key model, browser persistence or saved-key response/reveal capability. IPC responses expose only protection availability and configured booleans. Project exports never copy the app credential store; workers still receive no provider environment variables.

Main uses the release-pinned Electron 44.5.1 asynchronous `safeStorage` APIs and explicitly checks `isAsyncEncryptionAvailable()` on Windows. Only OS-encrypted buffers are written to `workspace/credentials/<provider>.json`, through a synchronized temporary file and replacement. Unavailable protection blocks saving with an actionable message, without a plaintext/session fallback. Replacing a key does not discard its existing encrypted value if encryption or saving fails. Corrupt/unreadable encrypted values fail closed; replace or remove them in Settings. No provider validation request is made and saving a key grants no spending authority.

Windows DPAPI protects against other Windows users, not other applications running as the same user. Project evidence and the registry are normal local files, not encrypted backups. [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage).

## Persistence boundary

`registry.json` version 1 stores project IDs, names, absolute private roots and active/trash status. `project.json` stores identity, display name, optional profile and creation time; exported metadata has no source/computer paths. Opening state and pending picker capabilities are session-only. The registry uses a flushed temporary file and rename; do not mistake that for database/filesystem transactions or power-loss durability. Abrupt termination between folder movement and registry commit may leave an orphan or stale reference. Do not automatically delete/adopt/replay it; preserve files for explicit repair. Ordinary errors roll back; crash reconciliation, SQLite jobs/ownership and snapshots remain [issue 53](https://github.com/ValenFelizia/instagram-to-opendesign/issues/53). Keep this registry format behind the broker when adding that job store.
