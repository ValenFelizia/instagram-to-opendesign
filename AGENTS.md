# Repository instructions

## Language

- Write project documentation, CSDD state, GitHub issue titles/bodies, PR titles/descriptions, review notes and project comments in English. Apply this rule even when the user's request is in Spanish.
- Keep generated reports in Spanish by default and preserve the explicit English option (`--lang en`).
- Preserve original evidence, quotations and confirmed brand copy in their original language. Identify translations as translations and retain identifiers, paths and references.
- Conversation with the user may follow the user's language.

The canonical requirement is the [language policy in `.csdd/specs.md`](.csdd/specs.md#language-policy). Contributor guidance is in [CONTRIBUTING.md](CONTRIBUTING.md).

## Coordination (CSDD external stub)

- `.csdd/todo.md` is `Mode: external`. Do not create In Progress / Ready to Land / Pending boards or `Owner` / `Agent` / `Scope` claims there.
- Pick work from open [GitHub Issues](https://github.com/ValenFelizia/instagram-to-opendesign/issues) and the stub's `Next:` policy; product priority is [Linear VAL-100](https://linear.app/valenf/issue/VAL-100/deliver-a-guided-workflow-from-brand-evidence-to-useful-creative-agent-context).
- Coordinate claims via issue assignees, linked PRs and branch ownership. Read `.csdd/specs.md`, `.csdd/decisions.md` and `.csdd/handoff.md` for durable truth and any remaining boundary risk.
- Native Windows gates before release work: [#51](https://github.com/ValenFelizia/instagram-to-opendesign/issues/51), [#52](https://github.com/ValenFelizia/instagram-to-opendesign/issues/52), [#58](https://github.com/ValenFelizia/instagram-to-opendesign/issues/58).
